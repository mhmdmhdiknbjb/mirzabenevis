# Visit Note Service — بک‌اند ابزارک پرونده‌نویسی هوشمند

این سرویس نسخه پروداکشن‌شده‌ی اسکریپت نوت‌بوک اولیه است: یک API واحد که فایل صوتی
یا متن ویزیت را می‌گیرد و پرونده پزشکی ساختاریافته فارسی (JSON) برمی‌گرداند.

## چه چیزی نسبت به نسخه نوت‌بوک تغییر کرده؟

| قبل (نوت‌بوک) | بعد (این سرویس) |
|---|---|
| کلیدهای API داخل کد، plaintext | کلیدها فقط از `.env` / environment variables خوانده می‌شوند |
| بدون timeout — یک تماس آویزان کل اجرا را قفل می‌کرد | timeout مجزا برای STT و LLM، قابل تنظیم در `.env` |
| اگر LLM دوم JSON خراب برگرداند، `{}` خالی برمی‌گشت | تلاش مجدد خودکار + اعتبارسنجی اسکیمای Pydantic؛ اگر باز هم نامعتبر بود، خطای صریح ۵۰۲ |
| اجرای خطی روی یک فایل محلی (`main()`) | endpoint HTTP واقعی (`POST /api/v1/visit-notes`) که ابزارک می‌تواند صدا بزند |
| بدون مدیریت خطا برای کاربر نهایی | پیام‌های خطای فارسی، مشخص و امن (بدون افشای stack trace) به همراه `request_id` برای پیگیری در لاگ |
| بدون CORS | CORS محدود به دامنه ابزارک شما (`ALLOWED_ORIGINS`) |
| فایل صوتی/متن بدون کنترل حجم | محدودیت حجم فایل صوتی (`MAX_AUDIO_SIZE_MB`) |

## راه‌اندازی محلی

```bash
cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env
# مقادیر STT_API_KEY و LLM_API_KEY را در .env با کلیدهای واقعی پر کن

uvicorn app.main:app --reload --port 8000
```

بعد از بالا آمدن سرویس:
- مستندات تعاملی: `http://localhost:8000/docs`
- health check: `http://localhost:8000/health`

## استفاده از API

```bash
# با فایل صوتی
curl -X POST http://localhost:8000/api/v1/visit-notes \
  -F "audio=@Recording.m4a"

# با متن آماده (مثلاً اگر پزشک تایپ کرده)
curl -X POST http://localhost:8000/api/v1/visit-notes \
  -F "transcript=بیمار از درد معده شکایت داشت..."
```

نمونه پاسخ موفق:

```json
{
  "status": "ok",
  "request_id": "....",
  "raw_transcript": "...",
  "corrected_transcript": "...",
  "note": {
    "yaddasht_pezeshk": "...",
    "khaleseh_bimar": "...",
    "list_daroha": [...],
    "peygiriha": {...},
    "khaleseh_moraje_baad": "..."
  }
}
```

نمونه پاسخ خطا (مثلاً timeout سرویس STT):

```json
{
  "status": "error",
  "request_id": "....",
  "stage": "transcription",
  "message": "سرویس تبدیل گفتار به متن پاسخ نداد (timeout). لطفاً دوباره تلاش کنید."
}
```

از `request_id` برای پیدا کردن جزئیات کامل خطا در لاگ سرور استفاده کن — این id به کلاینت
(ابزارک) هم برگردانده می‌شود تا در صورت تماس پزشک با پشتیبانی، قابل پیگیری باشد.

## نکات امنیتی و حریم خصوصی که قبل از اتصال به پذیرش۲۴ باید انجام بدی

این‌ها فراتر از دامنه‌ی این تحویل هستند ولی برای پروداکشن ضروری‌اند:

1. **چرخش کلیدها**: کلیدهایی که در نوت‌بوک اصلی hardcode شده بودند را از سرویس‌دهنده‌ها
   (Abrha، ParsPack) rotate/باطل کن — آن کلیدها دیگر امن محسوب نمی‌شوند.
2. **HTTPS اجباری**: این سرویس باید فقط پشت HTTPS (مثلاً پشت nginx/Caddy یا یک PaaS) قرار بگیرد.
3. **احراز هویت درخواست‌ها**: در حال حاضر endpoint باز است. قبل از عمومی شدن، باید یک لایه
   احراز هویت اضافه بشه (مثلاً بررسی `access_token` دریافتی از SDK همدست پذیرش۲۴ در هدر
   درخواست، طبق مرحله بعدی که در پاسخ قبلی توضیح دادم).
4. **نگه‌داری داده**: فایل صوتی و ترنسکریپت خام فعلاً در حافظه پردازش می‌شوند و روی دیسک
   نوشته نمی‌شوند (بر خلاف نسخه نوت‌بوک که `convertation.txt` می‌ساخت). اگر لاگ کامل نیاز
   داری، باید سیاست نگه‌داری/حذف و رمزنگاری آن را جدا مشخص کنی.
5. **Rate limiting**: چون این endpoint به دو سرویس پولی (STT و LLM) وصل است، حتماً یک
   rate limit (مثلاً به ازای هر پزشک/IP) قبل از انتشار عمومی اضافه کن تا در برابر سوءاستفاده
   یا باگ‌های فرانت‌اند محافظت شوی.

## مرحله بعدی

قدم بعدی، ساخت فرانت‌اند ابزارک (React/Vue) است که:
1. با SDK همدست پذیرش۲۴ کاربر را authenticate می‌کند
2. صدای ویزیت را ضبط یا آپلود می‌کند
3. به این endpoint (`/api/v1/visit-notes`) می‌فرستد
4. خروجی را به‌صورت فرم قابل ویرایش به پزشک نشان می‌دهد
